# FCR 规则包格式规范 v1.0

> 状态：**冻结**（`format_version: "1.0"`）。
> 本文件定义"一份规则包是什么、引擎如何裁决它"；不定义具体领域知识。
> 配套：`rulepack.schema.json`（机器可读）、`conformance.md`（一致性测试清单）。

## 1. 范围

一份**规则包（rulepack）**是一个 JSON 文件，包含：元数据、字段字典、规则列表。引擎读入规则包与一份**状态（state）**，执行前向链推理，输出最终状态与轨迹。

规则包**不含代码**。唯一的可执行语义来自：条件表达式（受限子集）与内建原子（3 个）。

## 2. 术语

| 术语 | 含义 |
|---|---|
| `state` | 一次诊断的输入/输出对象（JSON 对象）；字段名由规则包的 `fields` 声明 |
| `rule` | 一条 IF-THEN：`condition` 为真时执行 `actions` |
| `atom` | 最小的写入操作；内建 3 个（见 §5），不可扩展（v1） |
| `priority` | 规则排序键，**数值小者先触发** |
| `group` | 规则分组标签（`missing` / `red` / `candidate` / `verdict` / 自定义），仅用于阅读与轨迹 |
| `step` | 一次触发记录：规则 id、条件、动作、字段变更、变更前后状态 |
| `stable` | 已触发且无字段变更的规则集合；不再参与匹配 |
| `max_iter` | 最大轮数，默认 200；超限时 `stopped_reason = "max_iter"` |

## 3. 顶层结构

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `format` | string | 是（v1） | 固定 `"fcr/rulepack"`；缺失时按 legacy 模式读取 |
| `format_version` | string | 是 | 固定 `"1.0"` |
| `id` | string | 是 | 规则包标识，建议 kebab-case，全局唯一 |
| `version` | string | 是 | 规则包自身语义化版本，如 `"1.0.0"` |
| `title` | string | 是 | 一行标题 |
| `description` | string | 否 | 用途、适用对象、边界 |
| `license` | string | 否 | 建议 SPDX 标识，如 `"MIT"` |
| `status` | enum | 否 | `draft` / `stable`；缺省视为 `draft` |
| `fields` | object | 是 | 字段字典：`{ 字段名: {type, values?, description?} }` |
| `atoms` | array/object | 否 | 允许的原子 id 列表（v1 只会用内建 3 个）；对象形式保留兼容 |
| `rules` | array | 是 | 规则列表，非空 |

`fields.type` 取值：`enum` / `string` / `number` / `integer` / `boolean` / `array` / `object`。
`enum` 必须给 `values`。

## 4. 规则结构

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `rule_id` | string | 是 | 包内唯一；用作 stable 集键与轨迹标识 |
| `priority` | number | 是 | 数值小者先触发；建议分段：缺项 1–9、红旗 20–39、候选 60–69、结论 90–99 |
| `group` | string | 否 | 缺省 `default` |
| `condition` | string | 是 | 条件表达式（§6） |
| `description` | string | 是 | 人类可读的一句话结论 |
| `evidence` | object | 否 | `{kind, note, source?}`；`kind ∈ {heuristic, standard, literature, calibration}` |
| `actions` | array | 是 | 非空；每项 `{atom_id, params, output?}` |

`evidence.kind` 的含义：

- `heuristic`：经验规则，**未校准**，必须写明"未校准"；
- `standard`：领域标准做法（有共识，但非某篇文献专有）；
- `literature`：有可查文献支持，`source` 写作者+年份；
- `calibration`：用数据校准过，`source` 写数据集与指标。

## 5. 内建原子（v1）

| 原子 | 语义 | 幂等 |
|---|---|---|
| `set_field` | `state[key] = value`；**非幂等，必须带守卫** | 否 |
| `set_default` | 仅当字段为 `undefined/null/""/[]` 时写入 | 是 |
| `append_once` | 列表追加，已在列表内则跳过 | 是 |

`params` 的值一律为**字符串**。解析规则：

| 写法 | 含义 |
|---|---|
| `"state.get('x')"` / `"state['x']"` / `"state.x"` | 取状态字段 `x` 的值 |
| `"'text'"` / `'"text"'` | 字符串字面量 `text` |
| `"123"` / `"1.5"` / `"True"` / `"False"` / `"None"` | 对应字面量 |
| 其他 | 先尝试作为表达式求值，失败则作为裸字符串 |

> **陷阱**：`params.key` 若写成 `red_flags`（不带引号），会被当作字段引用 `state.red_flags`。必须写 `"'red_flags'"`。校验器把这一点列为**错误**。

## 6. 条件表达式（Python 风味子集）

支持：

- 字面量：数字、字符串、`True` / `False` / `None`、列表 `[a, b]`、字典 `{k: v}`；
- 比较：`== != > < >= <=`、`in` / `not in`、`is` / `is not`（`is` 等价于严格相等）；
- 逻辑：`and` / `or` / `not`（短路）；
- 算术：`+ - * / // % **`；
- 字段：`state.get('x')`、`state['x']`、`state.x`；未声明字段返回 `None`（不报错）；
- 内建函数：`len abs min max sum round str int float bool sorted list any all isinstance hasattr type range enumerate zip map filter print`；
- 字符串/列表/字典方法：`split/strip/startswith/endswith/replace/lower/upper`，`append/remove/count/index`，`get/keys/values/items/update/copy/setdefault` 等（见 `core/engine.mjs`）。

**不是** JavaScript：不要写 `===`、`&&`、`||`、`!`、`undefined`、`?.`、箭头函数。

## 7. 裁决语义（冻结）

```
rules ← 按 priority 升序排序（同优先级保持文件顺序）
state ← 深拷贝(初始状态)
stable ← ∅
for iteration = 1..max_iter:
    picked ← 第一条满足 (rule ∉ stable) 且 condition(state) 为真的规则
    if 没有 picked: stopped_reason ← "no_match"; break
    执行 picked 的全部 actions，记录每个字段变更
    记录 step：{iteration, rule_id, priority, group, condition, action_ids, changes, changed_fields, state_before, state_after}
    if 本步无字段变更: stable ← stable ∪ {picked}
    else: stable ← ∅
if iteration = max_iter: stopped_reason ← "max_iter"
返回 {final_state, steps, events, iterations, fires, stopped_reason}
```

由此产生三条硬约束：

1. **不变量**：`rules` 排序决定结果；同 `priority` 时以文件顺序为准。
2. **单条命中**：每轮只触发一条规则；要同轮触发多条，请拆成多条顺序规则。
3. **幂等原子**：`append_once` / `set_default` 重复触发不产生变更，因此会进入 stable 集；`set_field` 若无守卫会反复触发直到 `max_iter`。

## 8. 校验器检查项

**错误（exit 1）**

- JSON 解析失败；顶层不是对象；
- `rules` 缺失/非数组/为空；
- `rule_id` 缺失/重复/非字符串；
- `priority` 缺失/非数字；
- `condition` 缺失/解析失败（只解析，不求值）；
- `actions` 缺失/为空；`atom_id` 不在 `{set_field, set_default, append_once}`；
- `params.key` 未加引号（见 §5 陷阱）；
- `set_field` 的 `params.key` 目标字段在条件中无守卫（`is None` / `== None`）；
- `format` 存在但不是 `"fcr/rulepack"`；`format_version` 不是 `"1.0"`。

**警告（不影响退出码）**

- 条件引用了 `fields` 未声明的字段；
- 多条规则写同一标量字段（可能冲突）；
- 规则缺 `evidence`；
- `evidence.kind = "heuristic"` 但 `note` 未写"未校准"；
- `status` 缺失（按 draft 处理）。

## 9. 版本与兼容

- `format_version` 只在**破坏性变更**时递增；
- 新增可选字段不递增；
- 引擎语义（§7）属于格式的一部分，改动即破坏兼容；
- legacy 模式（无 `format` 字段）在 v1 内保留，v2 起可能移除。
